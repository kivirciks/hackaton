# Руководство администратора — локальный прототип

## Установка и запуск

Требуется Python 3.12 либо совместимая версия и зависимости из `requirements.txt`. Из корня распакованного архива:

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python -m collector_risk.server --artifacts artifacts --objects upload/справочник_объектов_диспетчер.csv
```

Интерфейс: `http://127.0.0.1:8080`; стартовые аккаунты `admin` и `dispatcher`, пароль `demo`. Сервер слушает localhost по умолчанию. Состояние хранится в `artifacts/feedback.sqlite3`, исходная модель и снимок — в `artifacts/`. Не публикуйте эту демо-конфигурацию в сети. Перемещение `artifacts/` вместе с готовым CSV и моделью сохраняет историю; перед копированием работающей БД используйте команду `backup`, а не простое копирование WAL-файлов.

## Роли и реестр

На странице «Роли и доступ» создайте роль с кодом латиницей и выберите права, затем создайте пользователя с этой ролью. `admin` системный, полные права зашиты в сервер; роль `dispatcher` существует при первом запуске. Права администратора `roles:manage`, `stream:write`, `objects:write`, `registry:sync`, `audit:read` нельзя передать иной роли. Для аудитора с единственным доступом к отчетности выберите `reports:read`. Изменение прав действует в открытой сессии. **Ограничение по отдельным `object_id` отсутствует**: при наличии права пользователь видит объекты этого вида целиком. Для промышленной эксплуатации это требуется реализовать.

Кнопка «Сверить с локальным CSV» выполняет upsert из `upload/справочник_объектов_диспетчер.csv`, фиксирует добавления, изменения и пропажи; это заглушка удаленного API. Локальные объекты имеют отрицательные ID и не возвращаются в исходный файл. Каналы датчиков загружаются из CSV при старте; добавленное локально оборудование хранится отдельно в SQLite.

## Данные, модель и демонстрационный поток

Готовые артефакты позволяют открыть UI без исходных архивов. Для полного пересчета верните `ext-journal-*.7z` и справочник каналов в `upload/`; 7z требует `libarchive.so.13`. Воспроизведение последних семи дней из `daily.csv` управляется на странице «Поступление данных»: шаг 10 записей, непрерывный запуск, пауза. Время источника историческое; времена приема и обработки локальные. Журнал и оповещения дедуплицируются; страница не подключена к промышленному потоку.

```bash
python -m collector_risk.operations benchmark --artifacts artifacts --object-id 20 --repeats 30
python -m collector_risk.operations backup --artifacts artifacts --destination backup-demo
python -m collector_risk.operations verify-backup --destination backup-demo
python -m collector_risk.scheduler --source upload --artifacts artifacts --utc-time 23:59 --once
python -m unittest discover -s tests -v
```

Последняя команда `scheduler` требует реально размещенных архивов/CSV журнала; в поставке их нет. Без `--once` процесс остается запущенным и запускает цикл в указанное время **UTC**. `operations.refresh` создает версию по хешу входных файлов, проверяет дневные данные; `scheduler` обучает модель и при сильном снижении AP удерживает выпуск. Файл подтверждений принимается отдельно и пока не используется как метка модели тревожных сигналов. Сравнение на меняющемся хронологическом тесте нельзя считать неизменной приемочной метрикой.

## Обслуживание и границы

Проверяйте результат `verify-backup`, цепочку аудита в отчете или `/api/audit`, даты источника, качество и ошибки обновления. Локальная копия не шифруется; расписание резервирования требует запущенного scheduler или внешнего планировщика. Локальные JSON с p95/p99 не подтверждают SLA на целевом сервере. Перед внедрением нужны реальные интеграции, отказоустойчивое хранилище, IdP/TLS, объектные права, внешний защищенный аудит, контроль задержки и испытания на целевом Linux.

Полный контракт API, включая ошибки, — [API.md](API.md); результат проверки этой поставки — [REVIEW.md](REVIEW.md).
